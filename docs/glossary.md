# Глоссарий проекта

Сводный список терминов, которые встречаются в ноутбуках и `README.md`.
Определения даны простым языком; в колонке «Зачем в проекте» указано, где термин
работает и на что влияет.

---

## 1. Данные и задача

| Термин | Что означает | Зачем в проекте |
|---|---|---|
| **Объект наблюдения** | Одна строка данных — один пациент с результатами обследования | Все метрики считаются по пациентам; строки не смешиваются |
| **Целевая переменная** | Столбец, который предсказывает модель; здесь `Status` | Определяет тип задачи — классификация, а не регрессия |
| **Класс** | Одно из значений целевой переменной: `C`, `CL`, `D` | Три класса неравной численности задают всю методику оценки |
| **Редкий класс** | Класс, которого в данных мало; здесь `CL` — 275 строк из 7 905 (3.5 %) | Из-за него доля верных ответов обманчива, а порог 0.5 не работает |
| **Дисбаланс классов** | Ситуация, когда классы представлены очень неравно | Требует стратификации, F-меры и отдельной настройки порога |
| **Признак** | Входной столбец модели: показатель, флаг, производное значение | 15 отобраны на стадии 1, ещё 7 добавлены на стадии 7 |
| **Инженерный признак** | Признак, вычисленный из исходных столбцов: логарифм, отношение, флаг | Даёт модели форму зависимости, которую она не построит сама |
| **Утечка цели** | Признак, который содержит ответ или известен только после исхода | `is_dead`, `N_Days` исключены, иначе оценка качества завышена |
| **Дублирование информации** | Два столбца описывают один и тот же факт в разной форме | Правило «одна информация — один столбец»: билирубин и его логарифм вместе не берутся |
| **Синтетические данные** | Набор, сгенерированный моделью по мотивам реального исследования | Ограничивает перенос выводов на клиническую практику |
| **Parquet** | Формат хранения таблиц с сохранением типов | Через него стадии обмениваются данными без потери точности |

## 2. Разбиение данных и валидация

| Термин | Что означает | Зачем в проекте |
|---|---|---|
| **Обучающая часть** | Данные, на которых модель учится; здесь 75 % строк | На ней же выполняется кросс-валидация и подбор гиперпараметров |
| **Контрольная часть** | Данные, которые не участвуют в обучении и выборе; здесь 25 % (1 977 строк) | Используется один раз — для итоговой оценки |
| **Стратификация** | Разбиение с сохранением доли классов в каждой части | Гарантирует, что редкий класс попадёт и в обучение, и в проверку |
| **Кросс-валидация** | Обучение и проверка несколько раз на разных частях данных | Даёт среднее и разброс вместо одной цифры |
| **Блок (фолд)** | Одна часть данных при кросс-валидации | По блокам считается разброс метрики |
| **`StratifiedKFold`** | Кросс-валидация с сохранением доли классов в каждом блоке | Основная схема проверки во всех стадиях |
| **`RepeatedStratifiedKFold`** | То же, но с несколькими повторами разных разбиений | Показывает, насколько уточняется оценка при повторах |
| **`LeaveOneOut`** | Проверка, где каждый объект по очереди становится контрольным | Сравнивается с кросс-валидацией по цене и точности |
| **Out-of-fold вероятности** | Предсказания, полученные для строк, когда они были в проверочном блоке | По ним выбирается порог редкого класса без подглядывания в тест |
| **Утечка данных** | Ситуация, когда в обучение попадает информация из проверки | Ломает оценку качества; проверяется численно в стадии 6 |
| **Разброс оценки** | Разница метрики между блоками или разбиениями | Определяет, какие улучшения вообще можно считать реальными |
| **Зерно случайности** | Число, фиксирующее случайные операции (`RANDOM_STATE = 42`) | Делает прогон воспроизводимым |

## 3. Метрики качества

| Термин | Что означает | Зачем в проекте |
|---|---|---|
| **Доля верных ответов** | Доля строк, где предсказанный класс совпал с истинным | Понятна, но при дисбалансе скрывает провал на редком классе |
| **Средняя доля верных по классам** | Доля верных, усреднённая по классам без учёта их численности | Показывает качество на малом классе |
| **Полнота (recall)** | Доля найденных объектов класса среди всех объектов этого класса | Полнота `CL` — главный показатель для пациента с трансплантацией |
| **Точность (precision)** | Доля верных среди предсказанных объектов класса | Показывает цену ложных срабатываний |
| **F-мера** | Совмещённая мера точности и полноты | Основная метрика сравнения вариантов |
| **F-мера macro** | F-мера, усреднённая по классам с равным весом | Не даёт забыть редкий класс |
| **F-мера weighted** | F-мера, усреднённая с весом по численности класса | Ближе к тому, что видит пользователь в среднем |
| **Лог-потеря** | Штраф за вероятности: уверенная ошибка наказывается сильнее | Мера качества вероятностей и калибровки модели |
| **Порог решения** | Граница вероятности, выше которой выбирается класс | Снижение порога `CL` поднимает полноту ценой точности |
| **Ложное срабатывание** | Модель предсказала класс, которого нет | Цена снижения порога: около 210 лишних пациентов при пороге 0.07 |

## 4. Модели и регуляризация

| Термин | Что означает | Зачем в проекте |
|---|---|---|
| **Baseline-модель** | Простейшая модель, с которой сравнивают всё остальное | Логистическая регрессия на 15 признаках — отправная точка |
| **Логистическая регрессия** | Модель, оценивающая вероятности классов линейной формулой | Основная модель проекта |
| **Коэффициент** | Вес признака в формуле модели | Показывает направление и силу влияния |
| **Свободный член** | Сдвиг формулы для каждого класса | Задаёт исходный уровень вероятности класса |
| **Гиперпараметр** | Настройка модели, которая не подбирается обучением | Степень полинома, сила и вид штрафа |
| **Регуляризация** | Ограничение величины коэффициентов | Борется с переобучением на большом числе столбцов |
| **L2-штраф** | Штраф за сумму квадратов коэффициентов | Сжимает веса, но не обнуляет их |
| **L1-штраф** | Штраф за сумму модулей коэффициентов | Обнуляет часть коэффициентов — отбор признаков |
| **ElasticNet** | Смесь L1 и L2 с долей `l1_ratio` | Позволяет и отбирать, и сжимать |
| **`C`** | Обратная сила штрафа: меньше `C` — сильнее ограничение | Ключевой гиперпараметр всех регуляризованных вариантов |
| **Переобучение** | Модель запоминает обучающие данные и теряет качество на новых | Демонстрируется на полиномах степеней 1–3 |
| **Полиномиальные признаки** | Квадраты и произведения исходных признаков | Дают модели нелинейность и взаимодействия |
| **Взаимодействие** | Совместное влияние двух признаков, отличное от суммы | Полином создаёт произведения, но не отношения |
| **Степень полинома** | Максимальная степень произведений | Вторая степень выбрана как компромисс |
| **Сходимость** | Ситуация, когда алгоритм обучения перестал улучшать решение | Без масштабирования модель не сходится за 2000 итераций |
| **`saga`** | Алгоритм обучения, поддерживающий L1 и ElasticNet | Нужен для разреженных решений |
| **Байесовская оптимизация** | Поиск гиперпараметров по модели вероятности хорошего результата | Optuna вместо полного перебора |
| **TPE** | Алгоритм байесовской оптимизации, используемый Optuna | `TPESampler(seed=RANDOM_STATE)` делает поиск воспроизводимым |

## 5. Подготовка признаков

| Термин | Что означает | Зачем в проекте |
|---|---|---|
| **Масштабирование** | Приведение столбцов к сопоставимым единицам | Без него штраф наказывает признаки неравномерно |
| **`StandardScaler`** | Вычитает среднее, делит на стандартное отклонение | Классический вариант, чувствителен к выбросам |
| **`MinMaxScaler`** | Сжимает значения в отрезок от 0 до 1 | Зависит от минимума и максимума, поэтому неустойчив |
| **`RobustScaler`** | Вычитает медиану, делит на межквартильный размах | Устойчив к выбросам; выбран для итоговой модели |
| **Медиана** | Значение, делящее выборку пополам | Основа `RobustScaler` |
| **Межквартильный размах** | Разница между 75-м и 25-м процентилями | Второй параметр `RobustScaler` |
| **Логарифмирование** | Сжатие правого хвоста распределения (`log1p`) | Выпрямляет скошенные лабораторные показатели |
| **`log1p`** | Логарифм от значения плюс один | Позволяет преобразовывать нули без потери строк |
| **Асимметрия (скошенность)** | Мера несимметричности распределения | До логарифма достигает 3.4, после — около 1.1–2.0 |
| **Сплайн** | Кусочно-гладкая кривая вместо одного многочлена | Проверенная альтернатива полиному, проигравшая 0.0101 |
| **Бинарный признак** | Столбец только из 0 и 1 | Флаги порогов и категориальные признаки |
| **`passthrough`** | Пропуск столбца без преобразования | Для бинарных столбцов масштабирование бессмысленно |
| **Клинический порог** | Граница показателя, после которой меняется трактовка | Даёт модели «ступеньку», которую линейная формула не построит |
| **Индекс-отношение** | Признак вида `A / B` | Полиномы дают произведения, но не отношения |
| **APRI** | `(AST / 40) / тромбоциты × 100` — маркер фиброза печени | Стандартный клинический индекс, понятный врачу |
| **Шкала Чайлда — Пью** | Клиническая шкала тяжести цирроза, построенная на порогах | Источник границ для билирубина и альбумина |

## 6. Организация кода

| Термин | Что означает | Зачем в проекте |
|---|---|---|
| **`Pipeline`** | Объект, объединяющий предобработку и модель | Исключает утечку: преобразования обучаются внутри блока |
| **`ColumnTransformer`** | Применяет разные преобразования к разным группам столбцов | Бинарные — как есть, числовые — через `RobustScaler` |
| **`GridSearchCV`** | Полный перебор заданной сетки гиперпараметров | Точка отсчёта для сравнения инструментов подбора |
| **`RandomizedSearchCV`** | Случайная выборка комбинаций из распределений | Дешевле полного перебора |
| **`HalvingGridSearchCV`** | Отсев слабых комбинаций на малом объёме данных | Самый дешёвый точный поиск в стадии 6 |
| **`HalvingRandomSearchCV`** | То же, но кандидаты выбираются случайно | Самый быстрый, но менее точный вариант |
| **`min_resources`** | Стартовый объём данных для отсева | При 100 строках 89 % оценок не определены, поэтому 600 |
| **`factor`** | Во сколько раз растёт объём данных на каждом шаге отсева | `factor = 2` — компромисс между скоростью и надёжностью |
| **`find_project_root()`** | Поиск папки проекта вверх по дереву каталогов | Ноутбук работает из любой текущей директории |
| **`RANDOM_STATE`** | Единая константа зерна случайности | Все разбиения и сэмплеры ссылаются на неё |

## 7. Анализ данных

| Термин | Что означает | Зачем в проекте |
|---|---|---|
| **φk (phik)** | Мера связи, работающая и с числами, и с категориями | Матрица связей на стадии 1 |
| **Kaplan — Meier** | Кривая вероятности дожить до момента времени с учётом цензурирования | Показывает, как стадия связана с выживаемостью |
| **Цензурирование** | Наблюдение закончилось раньше события | Пациенты `C` и `CL` не считаются умершими |
| **IQR-правило** | Выброс — значение за пределами 1.5 межквартильного размаха | Формальная проверка выбросов; отсечение отменено |
| **z-оценка** | Отклонение от среднего в стандартных отклонениях | Второе правило поиска выбросов |
| **MAD** | Медианное абсолютное отклонение | Устойчивое к выбросам третье правило |
| **ydata-profiling** | Библиотека автоматического отчёта о качестве данных | Часть 7 стадии 1 |
| **Streamlit** | Библиотека интерактивных дашбордов | `cirrhosis_dashboard.py` показывает результаты модели |
