# ml-project-practice-1

Проектный практикум 1 - Кейс 1

Анализ данных задачи **Multi-Class Prediction of Cirrhosis Outcomes**
с платформы Kaggle (Playground Series, Season 3, Episode 26): разведочный анализ (EDA),
проверка применимости линейной регрессии и многоклассовая классификация логистической
регрессией.

Трекер задач: https://docs.google.com/spreadsheets/d/1vKxLtHZbbPsE2l92k3tSlr8RJU-z_qAxzXUPyql2g8s/edit?usp=sharing

## О проекте

Работа разделена на три стадии, каждая — отдельный ноутбук в папке `project_notebooks/`:

**Стадия 1 — EDA** (`Stage_1_analysis.ipynb`): полный цикл разведочного анализа медицинского
датасета о пациентах с первичным билиарным циррозом — структура данных, качество, очистка от
клинически невозможных значений, статистические и клинические закономерности, влияющие на исход
наблюдения (выживание / трансплантация / смерть). В блоке 3.13 выполняется отбор
неинформативных признаков по четырём независимым мерам. В конце стадии очищенный датасет
сохраняется в `data/processed/train_clean.parquet`.

**Стадия 2 — регрессионный анализ** (`Stage_2_regression.ipynb`): проверка **возможности**
применения линейной регрессии к задаче предсказания клинического статуса пациента (`Status`)
по биохимическим анализам крови и анамнезу. Проверяются четыре предпосылки метода без обучения
модели; вердикт — линейная регрессия неприменима из-за категориальной цели. Стадия стартует
с того же `train_clean.parquet`, что гарантирует идентичность строк и признаков.

**Стадия 3 — классификация** (`Stage_3_classification.ipynb`): многоклассовая логистическая
регрессия как корректный ответ на категориальную цель. Основная часть стадии — работа с
дисбалансом классов (`CL` — 3.5 % наблюдений): метрики вместо accuracy, подбор порога решения
для редкого класса, веса классов, downsampling и upsampling, сравнение всех вариантов между
собой.

## Датасет

- **Название:** Multi-Class Prediction of Cirrhosis Outcomes
- **Источник:** Kaggle Playground Series S3E26
  (https://www.kaggle.com/competitions/playground-series-s3e26)
- **Первоисточник:** UCI Machine Learning Repository, *Cirrhosis Patient Survival Prediction*
- **Объём:** 7 905 строк × 19 столбцов (пропусков нет)
- **Целевая переменная:** `Status` с тремя классами
  - `C` — пациент жив на момент окончания наблюдения (цензурирован) — 4 965 (62.8 %)
  - `CL` — пациент жив благодаря трансплантации печени — 275 (3.5 %)
  - `D` — пациент умер — 2 665 (33.7 %)
- **Признаки:** возраст, пол, принимаемый препарат, лабораторные показатели
  (билирубин, альбумин, медь, щелочная фосфатаза, AST, холестерин, триглицериды,
  тромбоциты, протромбиновое время), клинические признаки (асцит, гепатомегалия,
  сосудистые «паучки», отёки), гистологическая стадия фиброза.

## Стадия 2 — регрессионный анализ (`Stage_2_regression.ipynb`)

**Цель:** проверить **возможность** применения линейной регрессии для предсказания клинического
статуса пациента с циррозом печени (`Status`) по биохимическим анализам крови и анамнезу.

**Формат раздела — необходимый минимум:** проверка предпосылок метода и вывод. Обучение модели,
метрики качества, интерпретация коэффициентов и логистическая регрессия вынесены в раздел 3:
линейная регрессия — инструмент для непрерывных целей, и проверка предпосылок показывает
несоответствие ещё до всякого моделирования.

| Блок | Содержание |
|------|-----------|
| **1. Импорты и настройки** | numpy, pandas |
| **2. Загрузка очищенных данных** | Чтение `data/processed/train_clean.parquet` (выход Stage 1), кодирование цели `Status` → `C=0, CL=1, D=2` |
| **3. Подготовка признаков** | One-hot кодирование категорий, исключение утечек цели (`is_dead`), дубликатов (`Age`, `Edema_num`, `is_severe`) и неинформативного `Drug` (обоснование — блок 3.13 Stage_1) |
| **4. Быстрая оценка применимости** | 4 проверки-предпосылки за секунды без обучения модели: тип цели, линейная связь с целью (Пирсон), линейность связи (Пирсон vs Спирмен), мультиколлинеарность между независимыми признаками (log-копии фильтруются как артефакт инжиниринга); вердикт по предпосылкам |
| **5. Выводы** | Глоссарий терминов, ответ на вопрос задачи, что переносится в раздел 3 |

**Результат:** предпосылка о непрерывности цели грубо нарушена — `Status` принимает три значения,
поэтому линейная регрессия для этой задачи неприменима (корректный инструмент — логистическая
регрессия, реализована в стадии 3). При этом признаки информативны (максимум |r| = 0.53 у
`log_Bilirubin`), а реальной мультиколлинеарности между независимыми признаками нет — отказ
относится к выбору метода, а не к качеству данных.

## Стадия 3 — классификация (`Stage_3_classification.ipynb`)

**Цель:** построить корректную модель предсказания `Status` и разобраться, как дисбаланс классов
влияет на выбор метода обучения и метрик. Класс `CL` — 275 строк (3.5 %), в тестовой выборке
всего 69.

**Логика стадии:** сама логистическая регрессия обучается за доли секунды, поэтому содержательная
часть — не модель, а обращение с редким классом: почему accuracy обманчива, как правильно
настраивать порог решения в мультиклассовой задаче и чем `class_weight` отличается от
сэмплирования.

| Блок | Содержание |
|------|-----------|
| **1. Импорты и настройки** | scikit-learn (модель, метрики, разбиение, масштабирование), matplotlib/seaborn |
| **2. Загрузка очищенных данных** | Чтение `data/processed/train_clean.parquet` (выход Stage 1), анализ дисбаланса `Status`; цель **не** кодируется порядково, в отличие от Stage 2 |
| **3. Подготовка признаков** | Тот же список исключений, что обоснован в блоке 3.13 Stage_1: `id`, `Status`, `is_dead` (утечка), `Drug` (неинформативен), `Age`, `Edema_num`, `is_severe`; one-hot категорий; 24 столбца |
| **4. Разбиение и стандартизация** | Стратификация по `Status` (75/25, `random_state=42`), `StandardScaler` с `fit` только на train |
| **5. Базовая модель** | Multinomial логистическая регрессия (softmax), `classification_report`, матрица ошибок, таблица из шести метрик |
| **6. Эксперимент с `N_Days`** | Подробный разбор природы утечки времени наблюдения, обучение модели без `N_Days`, сравнение метрик |
| **7. Порог решения для `CL`** | One-vs-rest вероятность класса `CL`, перебор порогов, графики recall/precision/F1, матрица ошибок при выбранном пороге |
| **8. Веса классов** | `class_weight='balanced'`, сравнение с базовой моделью |
| **9. Сэмплирование** | Ручные `downsample` / `upsample` на numpy с таблицей соответствия `RandomUnderSampler` / `RandomOverSampler`; применяются только к train и только после разбиения |
| **10. Сводное сравнение** | Шесть вариантов в одной таблице, выбор лучшего по каждой метрике с явным указанием направления оптимизации |
| **11. Интерпретация коэффициентов** | Топ-12 признаков по модулю коэффициента, разрез по классу `CL`, знаки, свободные члены, поправка на тривиальную коллинеарность `признак ↔ log-копия` |
| **12. Выводы** | Ответ на задачу, что дальше, глоссарий терминов |

**Результат:** базовая модель даёт accuracy 0.796 при log-loss 0.534, но recall класса `CL`
равен 0.014 — из 69 пациентов с трансплантацией найден 1. Разница accuracy / balanced accuracy
(0.796 против 0.534) — прямой диагноз дисбаланса.

| Вариант | accuracy | balanced acc | F1 macro | log-loss | recall CL |
|---|---|---|---|---|---|
| базовая (с `N_Days`) | 0.796 | 0.534 | 0.533 | **0.534** | 0.014 |
| без `N_Days` | **0.798** | 0.532 | 0.526 | 0.537 | 0.000 |
| порог `CL = 0.10` | 0.761 | 0.591 | **0.571** | **0.534** | 0.290 |
| `class_weight='balanced'` | 0.703 | 0.606 | 0.545 | 0.745 | 0.435 |
| downsampling | 0.690 | **0.616** | 0.542 | 0.851 | **0.493** |
| upsampling | 0.699 | 0.603 | 0.543 | 0.745 | 0.435 |

Лучший вариант зависит от метрики: для соревнования (log-loss) — базовая модель и вариант с
порогом (0.534); для равной цены всех классов (F1 macro) — порог `CL = 0.10` (0.571); для
максимального поиска редкого класса — downsampling (recall 0.493), но ценой 90 % обучающих
строк и худшей калибровки.

## Ключевые выводы

### По EDA (Stage 1)

1. **Целевая переменная `Status` несбалансирована** — класс `CL` встречается редко
   (275 наблюдений, 3.5 %), что требует взвешенных метрик и стратификации при разбиении выборок.
2. **Лабораторные признаки сильно скошены вправо** (`Bilirubin`, `Copper`, `Alk_Phos`,
   `SGOT`) — обязательны `log1p`-преобразования перед линейными моделями.
3. **`Stage` согласуется с клиническими показателями**: чем выше стадия, тем выше
   медианные `Bilirubin`, `Copper`, `Prothrombin` и ниже `Albumin`, `Platelets`.
4. **Kaplan-Meier кривые по стадиям статистически значимо разделяются** (log-rank
   `p < 0.05`) — `Stage` является сильным прогностическим признаком.
5. **Мультиколлинеарность** между `SGOT ↔ Alk_Phos` и `Bilirubin ↔ Copper` требует
   регуляризации или отбора признаков перед линейными моделями.
6. **Формальные IQR-выбросы — это реальные тяжёлые пациенты**, а не ошибки ввода.
   Прямое удаление по правилу 1.5·IQR недопустимо; корректная стратегия — log-преобразование
   и устойчивые метрики (MAD, percentile rank).
7. **Неинформативные признаки отобраны формально, а не «на глаз»** (блок 3.13). Из 28 признаков
   ни один не константен; исключаются только `id` (технический ключ) и `Drug` (φk = 0.013,
   Cramér's V = 0.027 при χ² p = 0.053). Признаки `Sex` (92.8 % «F») и `Ascites` (95.2 % «N»)
   остаются: высокая доля модального значения не означает отсутствия связи с целью
   (V = 0.131 и 0.277 соответственно).

### По регрессии (Stage 2)

8. **Линейная регрессия для этой задачи неприменима** — предпосылка о непрерывности цели
   грубо нарушена: `Status` принимает три значения, а модель выдаёт произвольные вещественные
   числа. Быстрая проверка предпосылок заняла ~30 секунд и дала тот же управленческий вывод,
   что занял бы полный цикл моделирования.
9. **Данные при этом пригодны для моделирования** — признаки информативны (максимум
   |r| = 0.53 у `log_Bilirubin`), реальной мультиколлинеарности между независимыми
   признаками нет (сильнейшая пара |r| = 0.66, `Ascites_Y ↔ Edema_Y`).
10. **Рекомендация подтверждена практикой:** корректный инструмент — многоклассовая логистическая
   регрессия с метриками классификации. Она реализована в стадии 3; обучение линейной регрессии,
   метрики R²/MAE/RMSE и диагностика остатков в проект не вошли, поскольку проверка предпосылок
   заранее показала некорректность такой постановки.

### По классификации (Stage 3)

11. **Accuracy при дисбалансе вводит в заблуждение.** Базовая модель: accuracy 0.796, но
    balanced accuracy 0.534 и recall класса `CL` 0.014 (1 пациент из 69). Основная метрика
    сравнения вариантов — F1 macro, а log-loss остаётся метрикой соревнования.
12. **Порог решения в мультиклассовой задаче настраивается через one-vs-rest.** «Сместить 0.5»,
    как в бинарной классификации, нельзя: softmax даёт три вероятности в сумме равные 1, и
    правило перестаёт быть однозначным. Порог `P(CL) > 0.10` поднял recall `CL` с 0.014 до 0.290
    и F1 macro с 0.533 до 0.571, не изменив log-loss.
13. **`class_weight='balanced'` — самый дешёвый способ увидеть редкий класс:** recall `CL` 0.435
    без потери данных, но log-loss ухудшается до 0.745 (модель теряет калибровку).
14. **Сэмплирование не улучшает линейную модель.** Downsampling даёт лучший recall `CL` (0.493)
    и наихудший log-loss (0.851), потому что оставляет 618 из 5 928 обучающих строк; upsampling
    почти повторяет `class_weight` — для линейной модели это математически близкие приёмы.
15. **Утечка `N_Days` подтверждена числами и оказалась слабой для линейной модели.** Без признака
    accuracy даже выше (0.798 против 0.796), log-loss хуже на 0.0033. Признак оставлен (он легален
    по контракту соревнования), но при переходе к ансамблям или survival-моделям его вклад нужно
    перепроверить: там нелинейность `N_Days` используется полностью.
16. **Выбор «лучшей» модели неразрывно связан с выбором метрики.** В сводной таблице стадии
    победители разные: log-loss — базовая модель, F1 macro — порог `CL = 0.10`, balanced accuracy
    и recall `CL` — downsampling. Единого правильного ответа вне постановки задачи не существует.

## Методология анализа

Работа построена по классической схеме EDA — от проверки качества к одномерному,
многомерному и сегментированному анализу, затем — проверка предпосылок базовой модели
и корректная классификация:

- **Качество данных:** пропуски, дубликаты, биологически невозможные значения,
  клинические диапазоны, согласованность категориальных признаков, формальные
  статистические выбросы (IQR, z-score, MAD).
- **Одномерный анализ:** описательные статистики, гистограммы + KDE, violin/box,
  QQ-plot, тесты нормальности, частоты категориальных признаков.
- **Survival-специфика:** Kaplan-Meier кривые и log-rank тест по `Status` и `Stage`
  (методы, отсутствующие в базовых matplotlib/seaborn).
- **Многомерный анализ:** pairplot, корреляция Пирсона, матрица φk (phik) —
  универсальная мера связи для смешанных типов признаков.
- **Сегментированный анализ:** сравнение профилей стадий и групп исхода через
  radar chart на percentile rank.
- **Автоматизация:** ydata-profiling как чек-лист, Streamlit-дашборд для интерактивного
  исследования подгрупп.
- **Проверка предпосылок (Stage 2):** быстрая оценка применимости линейной регрессии
  через корреляционные метрики (Пирсон, Спирмен) и анализ мультиколлинеарности.
- **Отбор признаков (Stage 1, блок 3.13):** четыре независимые меры связи с целью — φk (phik),
  mutual information, Cramér's V с χ²-тестом для категориальных и Kruskal-Wallis для числовых
  признаков; решение принимается по размеру эффекта, а не по p-value.
- **Классификация (Stage 3):** multinomial логистическая регрессия, сравнение методов работы с
  дисбалансом (порог решения, веса классов, сэмплирование) на одной стратифицированной
  тестовой выборке, интерпретация коэффициентов по классам.

## Ограничения линейной регрессии для задачи классификации

- **Номинальная цель закодирована порядково** (`C=0, CL=1, D=2`): модель предполагает равные
  «шаги» между классами, что неверно клинически — промежуточных статусов не существует.
- **Предсказания выходят за диапазон [0, 2]**: линейная гиперплоскость не ограничена
  значениями цели, она вернёт значения вроде −0.4 или 2.7, не соответствующие ни одному классу.
- **Метрики качества регрессии неинтерпретируемы**: R², MAE и RMSE измеряют ошибку в единицах
  условной шкалы 0–2; «ошибка 0.5» не отвечает на практический вопрос «выживёт ли пациент».
- **Мультиколлинеарные пары** (`Bilirubin ↔ log_Bilirubin` и др.) — артефакт инженерного
  кодирования, а не свойство данных: между независимыми признаками сильных коллинеарных
  пар нет (максимум |r| ≈ 0.66, `Ascites_Y ↔ Edema_Y`).
- **Остатки не нормальны** из-за дискретной цели: три «полосы» вокруг значений 0/1/2.
- **Оценка на одном разбиении 75/25**: для устойчивой оценки требуется k-fold CV.
