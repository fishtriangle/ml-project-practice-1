## О проекте

Работа разделена на две стадии, каждая — отдельный ноутбук в папке `project_notebooks/`:

**Стадия 1 — EDA** (`Stage_1_analysis.ipynb`): полный цикл разведочного анализа медицинского
датасета о пациентах с первичным билиарным циррозом — структура данных, качество, очистка от
клинически невозможных значений, статистические и клинические закономерности, влияющие на исход
наблюдения (выживание / трансплантация / смерть). В конце стадии очищенный датасет сохраняется
в `data/processed/train_clean.parquet`.

**Стадия 2 — регрессионный анализ** (`Stage_2_regression.ipynb`): проверка возможности и качества
линейной регрессионной модели на очищенной выборке — предсказание клинического статуса пациента
по биохимическим анализам крови и анамнезу. Стадия стартует с того же `train_clean.parquet`,
что гарантирует идентичность строк и признаков.

## Датасет

- **Название:** Multi-Class Prediction of Cirrhosis Outcomes
- **Источник:** Kaggle Playground Series S3E26
  (https://www.kaggle.com/competitions/playground-series-s3e26)
- **Первоисточник:** UCI Machine Learning Repository, *Cirrhosis Patient Survival Prediction*
- **Объём:** 7 905 строк × 19 столбцов (пропусков нет)
- **Целевая переменная:** `Status` с тремя классами
  - `C` — пациент жив на момент окончания наблюдения (цензурирован) — 4 965 (62.8 %)
  - `CL` — пациент жив благодаря трансплантации печени — 275 (3.5 %)
  - `D` — пациент умер — 2 665 (33.7 %)
- **Признаки:** возраст, пол, принимаемый препарат, лабораторные показатели
  (билирубин, альбумин, медь, щелочная фосфатаза, AST, холестерин, триглицериды,
  тромбоциты, протромбиновое время), клинические признаки (асцит, гепатомегалия,
  сосудистые «паучки», отёки), гистологическая стадия фиброза.

## Стадия 2 — регрессионный анализ (`Stage_2_regression.ipynb`)

**Цель:** проверить **возможность** применения линейной регрессии для предсказания клинического
статуса пациента с циррозом печени (`Status`) по биохимическим анализам крови и анамнезу.

**Формат раздела — необходимый минимум:** проверка предпосылок метода и вывод. Обучение модели,
метрики качества, интерпретация коэффициентов и логистическая регрессия вынесены в раздел 3:
линейная регрессия — инструмент для непрерывных целей, и проверка предпосылок показывает
несоответствие ещё до всякого моделирования.

| Блок | Содержание |
|------|-----------|
| **1. Импорты и настройки** | numpy, pandas |
| **2. Загрузка очищенных данных** | Чтение `data/processed/train_clean.parquet` (выход Stage 1), кодирование цели `Status` → `C=0, CL=1, D=2` |
| **3. Подготовка признаков** | One-hot кодирование категорий, исключение утечек цели и дубликатов |
| **4. Быстрая оценка применимости** | 4 проверки-предпосылки за секунды без обучения модели: тип цели, линейная связь с целью (Пирсон), линейность связи (Пирсон vs Спирмен), мультиколлинеарность между независимыми признаками (log-копии фильтруются как артефакт инжиниринга); вердикт по предпосылкам |
| **5. Выводы** | Глоссарий терминов, ответ на вопрос задачи, что переносится в раздел 3 |

**Результат:** предпосылка о непрерывности цели грубо нарушена — `Status` принимает три значения,
поэтому линейная регрессия для этой задачи неприменима (корректный инструмент — логистическая
регрессия). При этом признаки информативны (максимум |r| = 0.53 у `log_Bilirubin`), а реальной
мультиколлинеарности между независимыми признаками нет — отказ относится к выбору метода, а не
к качеству данных.

## Ключевые выводы

### По EDA (Stage 1)

1. **Целевая переменная `Status` несбалансирована** — класс `CL` встречается редко

2. **Лабораторные признаки сильно скошены вправо** (`Bilirubin`, `Copper`, `Alk_Phos`,

3. **`Stage` согласуется с клиническими показателями**: чем выше стадия, тем выше

4. **Kaplan-Meier кривые по стадиям статистически значимо разделяются** (log-rank

5. **Мультиколлинеарность** между `SGOT ↔ Alk_Phos` и `Bilirubin ↔ Copper` требует

6. **Формальные IQR-выбросы — это реальные тяжёлые пациенты**, а не ошибки ввода.
   Прямое удаление по правилу 1.5·IQR недопустимо; корректная стратегия — log-преобразование
   и устойчивые метрики (MAD, percentile rank).

### По регрессии (Stage 2)

7. **Линейная регрессия для этой задачи неприменима** — предпосылка о непрерывности цели
   грубо нарушена: `Status` принимает три значения, а модель выдаёт произвольные вещественные

## Методология анализа

Работа построена по классической схеме EDA — от проверки качества к одномерному,
многомерному и сегментированному анализу, затем — проверка предпосылок базовой модели:

- **Качество данных:** пропуски, дубликаты, биологически невозможные значения,
  клинические диапазоны, согласованность категориальных признаков, формальные
  статистические выбросы (IQR, z-score, MAD).
- **Одномерный анализ:** описательные статистики, гистограммы + KDE, violin/box,
  QQ-plot, тесты нормальности, частоты категориальных признаков.
- **Survival-специфика:** Kaplan-Meier кривые и log-rank тест по `Status` и `Stage`
  (методы, отсутствующие в базовых matplotlib/seaborn).
- **Многомерный анализ:** pairplot, корреляция Пирсона, матрица φk (phik) —
  универсальная мера связи для смешанных типов признаков.
- **Сегментированный анализ:** сравнение профилей стадий и групп исхода через
  radar chart на percentile rank.
- **Автоматизация:** ydata-profiling как чек-лист, Streamlit-дашборд для интерактивного
  исследования подгрупп.
- **Проверка предпосылок (Stage 2):** быстрая оценка применимости линейной регрессии
  через корреляционные метрики (Пирсон, Спирмен) и анализ мультиколлинеарности.

## Ограничения линейной регрессии для задачи классификации

- **Номинальная цель закодирована порядково** (`C=0, CL=1, D=2`): модель предполагает равные
  «шаги» между классами, что неверно клинически — промежуточных статусов не существует.
- **Предсказания выходят за диапазон [0, 2]**: линейная гиперплоскость не ограничена
  значениями цели, она вернёт значения вроде −0.4 или 2.7, не соответствующие ни одному классу.
- **Метрики качества регрессии неинтерпретируемы**: R², MAE и RMSE измеряют ошибку в единицах
  условной шкалы 0–2; «ошибка 0.5» не отвечает на практический вопрос «выживёт ли пациент».
- **Мультиколлинеарные пары** (`Bilirubin ↔ log_Bilirubin` и др.) — артефакт инженерного
  кодирования, а не свойство данных: между независимыми признаками сильных коллинеарных
  пар нет (максимум |r| ≈ 0.66, `Ascites_Y ↔ Edema_Y`).
- **Остатки не нормальны** из-за дискретной цели: три «полосы» вокруг значений 0/1/2.
- **Оценка на одном разбиении 75/25**: для устойчивой оценки требуется k-fold CV.
